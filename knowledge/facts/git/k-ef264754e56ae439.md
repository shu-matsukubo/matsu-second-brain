# 内容

コミットの単位を整えるには、ファイル単位または差分のまとまり（hunk）単位でステージする。ステージ後は`git diff --staged`で次のコミット候補を確認する。

`git diff`は作業ツリーとインデックスを比較し、`git diff --staged`は、比較先を指定しなければインデックスとHEADを比較する。まだHEADがない初回コミット前は、ステージ済みの全変更を表示する。

## ファイル単位で選ぶ

```bash
git add path/to/file
git diff --staged
```

`git add <file>` は、その時点のファイル内容をインデックスへ追加する。ファイルをさらに編集した場合、その後の変更は自動では追加されないため、必要なら再度 `git add` を実行する。

## hunk 単位で選ぶ

```bash
git add -p
git diff --staged
```

`git add -p` は、作業ツリーとインデックスの差分を順に表示し、選んだ hunk だけをインデックスへ追加する。同じファイルに複数の作業内容が混在した場合でも、コミットに含める変更を分けながらセルフレビューできる。

## ステージから外す

```bash
git restore --staged path/to/file
```

`git restore --staged <file>`は、HEADが存在し、復元元を別途指定しない場合、インデックスをHEADの状態へ戻す。これにより変更を次のコミット対象から外し、作業ツリーの編集内容は残す。

`git restore <file>`は、既定では作業ツリーをインデックスの内容へ戻すため、ステージしていない編集を失う可能性がある。復元先は`--staged`と`--worktree`、復元元は`--source`で変わる。`--staged --worktree`を併用すれば両方が復元対象になるため、実行前に対象を確認する。

## 広く追加する場合の確認

```bash
git add .
git status
git diff --staged
```

`git add .`は、実行したディレクトリ以下の追加・変更・削除をまとめてインデックスへ反映する。通常、ignoreルールに該当する未追跡ファイルは追加しない。意図しないファイルを含める可能性があるため、直後に `git status` と `git diff --staged` で対象と内容を確認する。

ローカル専用の未追跡ファイルを継続して除外するには、`.gitignore`などのignoreルールを使う。すでにGitが追跡しているファイルは、ignoreルールへ追加するだけでは対象から外れない。追跡済みかどうかと、共有する除外ルールか個人用の除外ルールかを分けて判断する。
