      # LINE Messaging API の送信方式を選ぶ\r

      \r

      LINE Messaging API では、宛先の指定方法と送信のきっかけに応じて送信方式を選ぶ。個別通知には push、複数の既知ユーザーには multicast、条件で絞る配信には narrowcast、友だち全員への配信には broadcast、利用者からのイベントへの応答には reply を使う。\r

      \r

      ## 送信方式\r

      \r

      | 方式 | 適する用途 | 宛先・条件 |\r

      | --- | --- | --- |\r

      | push | 個別の利用者へ任意のタイミングで通知する | ユーザー ID、グループ ID、トークルーム ID を指定する |\r

      | multicast | 複数の既知ユーザーへ同じ内容を送る | 複数のユーザー ID を指定する |\r

      | narrowcast | 属性やオーディエンスで対象を絞って配信する | オーディエンスや属性条件を指定する |\r

      | broadcast | 公式アカウントの友だち全員へ配信する | 宛先を個別指定しない |\r

      | reply | 利用者から届いたイベントへ応答する | Webhook で受け取った reply token を使う |\r

      \r

      push を使う場合は、アプリの利用者と LINE のユーザー ID を安全に対応付ける。reply token は有効期限が短いため保存して後から使う用途には向かない。\r

      \r

      ## メッセージ数の考え方\r

      \r

      メッセージ数は吹き出し数ではなく、原則として「送信リクエスト数 × 受信者数」で数える。1回のリクエストには最大5個のメッセージオブジェクトを含められるが、それ自体でカウントは増えない。ブロック済みなどで配信されない宛先もカウントから除外され、reply は料金プラン上のメッセージ数に数えられない。\r

      \r

      具体的な無料通数、追加料金、上限は契約地域とプランの最新情報を確認する。\r

# 内容

LINE Messaging APIは、LINE公式アカウントから利用者へメッセージを送るAPI。送信先と契機に応じて方式を選ぶ。

## 送信方式

| 方式 | 宛先・契機 |
| --- | --- |
| push | ユーザー・グループ・トークルームへの送信 |
| multicast | 指定した複数ユーザーへの同じ内容の送信 |
| narrowcast | 属性・オーディエンスで絞ったユーザーへの配信 |
| broadcast | 公式アカウントの友だち全員への配信 |
| reply | Webhookイベントのreply tokenによる応答 |

1リクエストには最大5個のメッセージオブジェクトを含められる。pushには友だち追加や直近のメッセージ受信などの送信条件があり、任意のユーザーIDへ無条件に届くわけではない。reply tokenは一度だけ使え、Webhook受信後1分以内に利用する。

## 準備と認証

LINE公式アカウントでMessaging APIを有効にし、チャネルを作る。API呼び出しにはチャネルアクセストークンを使い、利用者からのイベントを受ける場合はHTTPSのWebhook受信先を設定する。

トークンにはv2.1、ステートレス、短期、長期などの発行方式がある。公式のBot構築ガイドはv2.1を推奨する。v2.1の発行では署名用の秘密鍵・公開鍵を生成し、公開鍵を登録してJWTを作る。送信時に使うトークンと、その発行用の鍵を区別する。認証情報の保存方法は関連するシークレット管理を参照する。

## 送信数と上限

通数は各送信で実際に届ける人数に基づき、同じリクエスト内のメッセージオブジェクト数では増えない。ブロック済みなど届かない宛先は除かれる。push・multicast・narrowcast・broadcastはプランの通数に計上され、replyは計上されない。

月間の送信可能上限を超えると、エラーになり送信されない。無料通数を超える追加配信が可能なプランもあるため、無料通数と最終的な送信可能上限を区別する。料金・上限は地域とプランで異なる。

## 再送

push・multicast・narrowcast・broadcastでは、初回から`X-Line-Retry-Key`を付け、失敗時にも同じ宛先・内容・キーで再送すると重複実行を防げる。キーは初回から24時間有効で、受理済みは409になる。受理と実際の配達は異なり、再送キーは配達を保証しない。
