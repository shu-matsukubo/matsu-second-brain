# 内容

Windows コンテナには Windows の実行基盤が必要で、Linux の Docker Engine 上でそのまま動かすことはできない。ホストOSのコンテナ機能、利用する実行基盤、分離方式とイメージの互換性を分けて確認する。

## ホストOSとDocker Desktopの条件

Microsoftはコンテナ機能の対象にWindows Server 2016以降、Windows 10 Professional／Enterprise（1607以降）、Windows 11 Pro／Enterpriseを挙げている。この機能上の対象範囲は、現在の製品サポートやDocker Desktopの対応範囲を保証するものではない。Hyper-V分離にはHyper-Vロールが必要で、仮想マシン内のホストで利用する場合は入れ子の仮想化などの追加条件がある。

2026-11-17確認のDocker Desktop公式資料では、Windowsコンテナには次の条件がある。

- Windows 10／11のProfessionalまたはEnterpriseと、x86_64版の全ユーザー向けインストールを使う。ユーザー単位のインストールとArm版ではWindowsコンテナを利用できず、Home／EducationはLinuxコンテナのみが対象となる。
- 資料に記載されたOS要件は、Windows 10 22H2（build 19045）、Windows 11 23H2（build 22631）以降。これに加えてMicrosoftのサービス提供期間内であることが条件となるため、バージョン名の記載だけで現在サポート中とは判断しない。
- Hyper-VとContainersのWindows機能、対応するハードウェア仮想化などの要件を満たす。Windows ServerはDocker Desktopのサポート対象ではなく、Server用の実行基盤を別途選ぶ。

Docker Desktopのメニューによる切替は、Docker CLIが接続するLinux／Windowsデーモンの切替である。一つのデーモンで両OSのイメージを区別なく実行する仕組みではない。

## 分離方式とバージョン互換性

プロセス分離はホストとカーネルを共有するため、ホストとイメージのバージョンの組み合わせに制約がある。Hyper-V分離は最適化された仮想マシン内にコンテナ用のWindowsカーネルを持ち、異なるOSバージョンを扱える組み合わせがある。

利用可否はMicrosoftの互換表で、ホストOS、ベースイメージ、分離方式ごとに確認する。buildやrevisionの一致条件と例外もあるため、「同じWindowsなら動く」「Hyper-V分離ならどの組み合わせでも動く」とは一般化しない。非対応の場合は、対応イメージや、利用可能な別の分離方式を検討する。

## GUIアプリケーションの制約

Windowsコンテナは対話的なデスクトップGUIをサポートしない。実行時にデスクトップ操作を必要とするアプリケーションは、そのままでは対象外となる。インストーラーだけがGUIを必要とする場合、サイレントインストールに変更できればコンテナ化できる可能性があるが、それだけでアプリ全体の対応は保証されない。

GUI APIの利用と、GUI画面を表示・操作することは別である。APIの必要性だけからコンテナ化不可と判断せず、ベースイメージとアプリの要件を確認する。対話的なデスクトップが必要なら、仮想マシンなど別の実行方式を検討する。
