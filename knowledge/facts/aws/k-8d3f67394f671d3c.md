      # API Gateway の REST API と HTTP API における JWT 認証\r

      \r

      Amazon API Gateway には REST API と HTTP API がある。外部の OpenID Connect（OIDC）または
      OAuth 2.0 プロバイダーが発行する JWT を、API Gateway の標準機能で直接検証したい場合は HTTP API
      が適している。\r

      \r

      ## オーソライザーの違い\r

      \r

      | 認可方式 | REST API | HTTP API |\r

      | --- | --- | --- |\r

      | JWT オーソライザー | 非対応 | 対応 |\r

      | Amazon Cognito | Cognito User Pools オーソライザー | JWT オーソライザーとして利用可能 |\r

      | Lambda オーソライザー | 対応 | 対応 |\r

      | IAM 認可 | 対応 | 対応 |\r

      \r

      HTTP API の JWT オーソライザーは、設定した issuer と audience
      を基に署名や標準クレームを検証し、必要に応じてルートごとのスコープも検証する。Cognito に限定されず、要件を満たす OIDC / OAuth
      2.0 プロバイダーを利用できる。\r

      \r

      REST API の組み込み JWT 系認可は Cognito User Pools 向けであり、汎用 JWT オーソライザーはない。Cognito
      以外のプロバイダーが発行する JWT を使う場合は、通常は Lambda オーソライザーでトークン検証を実装する。\r

      \r

      Lambda オーソライザーは REST API と HTTP API
      の両方で利用できるため、独自の認証・認可ロジックが必要な場合に選択できる。ただし、Lambda
      の実行、エラー処理、キャッシュ、鍵のローテーションなどの運用が増える。\r

      \r

      ## 選び方\r

      \r

      - 外部 IdP の JWT を標準機能で検証したい場合は HTTP API を優先する。\r

      - Cognito User Pools を利用し、REST API 固有の機能が必要なら REST API も選択肢になる。\r

      - API キー、クライアント単位のスロットリング、リクエスト検証、AWS WAF、プライベート API、キャッシュなどが必要なら REST API
      を検討する。\r

      - REST API 固有の機能が不要なら、機能を絞った低価格な HTTP API を検討する。\r

      - 標準オーソライザーで表現できない認可要件がある場合は、どちらでも Lambda オーソライザーを利用できる。\r

      \r

# 内容

Amazon API GatewayのREST APIとHTTP APIでは、利用できる認可方式と周辺機能が異なる。HTTP APIは汎用の組み込みJWTオーソライザーを提供する。REST APIでJWTを扱えないという意味ではなく、Cognito User PoolsやLambdaオーソライザーを使う経路がある。

## 認可方式の違い

| 方式 | REST API | HTTP API |
| --- | --- | --- |
| 汎用の組み込みJWTオーソライザー | なし | あり |
| Amazon Cognito User Pools | `COGNITO_USER_POOLS` | JWTオーソライザーで利用 |
| Lambdaオーソライザー | あり | あり |
| IAM認可 | あり | あり |

HTTP APIのJWTオーソライザーは、設定したissuer・audienceなどに基づいて署名とクレームを検証する。ルートにscopeを要求することもできる。署名検証だけでIDトークンとアクセストークンを自動判別するものではなく、APIの要件に合わせてscope等の条件を設定する。

REST APIのCognito認可では、メソッドの認可scopeを設定しない場合と設定する場合で、IDトークン・アクセストークンの扱いが変わる。Cognito以外のJWT検証や独自認可にはLambdaオーソライザーが選択肢になる。その検証ロジックやキャッシュは別途設計する。RESTとHTTPではLambdaオーソライザーのイベント・応答形式にも違いがある。

## 機能と費用の比較範囲

AWSの比較表では、APIキー、クライアント別の流量制御、リクエスト検証、AWS WAF連携、Private APIエンドポイント、キャッシュはREST API側の機能として示されている。HTTP APIのPrivateなバックエンド統合と、API自体のPrivateエンドポイントは別の項目である。

AWSはHTTP APIを、機能を絞って低価格で提供する設計と説明している。ただし、実費には呼び出し・データ転送・キャッシュや連携サービス等の利用条件が関係する。料金を判断するときは対象の利用条件を公式料金表に照らす。このノートは具体的な単価・無料枠・リージョン別料金や総費用の見積もりを確定するものではない。

認可方式だけでAPI種別を決めず、必要な機能と運用を合わせて選ぶための比較材料として扱う。本人の採用意思を示すノートではない。
