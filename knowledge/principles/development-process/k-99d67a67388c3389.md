# 内容

AI開発Workflowの完了条件は、PRの最新コミットで必要な検証が成功することとする。PRを作成または更新したら、GitHub CLIやAPIを使って対象のHEAD SHAと必須CIの結果を照合し、全件の成功を確認する。

CIが失敗したらログから原因を調べ、作業範囲内の修正を検証してPRへ反映する。更新後は新しいHEAD SHAで必須CIの成功を確認する。検証を有効に保ち、未起動や実行中のチェックは結果が確定するまで待つ。待機時間と修正回数に上限を設け、上限に達するか復旧できないときは、失敗箇所とともに未完了として報告する。

この開発Workflowでは、CI成功後のPRレビューとマージを人間が担当する。

```text
## AI開発WorkflowはCI成功まで責任を持つ

### 背景
AIがPRを作成した直後に完了報告すると、
CI失敗の発見と再依頼が人間の仕事になる。

### 設計方針
PR作成をWorkflowの完了条件にしない。

1. PRを作成・更新する
2. 最新HEAD SHAの必須CI完了を待つ
3. 失敗したらログから原因を調査する
4. 修正・検証してPRへ反映する
5. 更新後のCI成功を再確認する

### 制約
- 未起動・実行中を成功と扱わない
- 待機・修正回数に上限を設ける
- CIを通すために検証を無効化しない
- 復旧不能なら未完了として報告する
- 人間によるPRレビュー・マージは維持する

### 実装
GitHub CLIやAPIによる機械的な判定を優先する。

### 原則
AIの完了条件は操作の終了ではなく、
要求された検証結果の達成で定義する。
```
