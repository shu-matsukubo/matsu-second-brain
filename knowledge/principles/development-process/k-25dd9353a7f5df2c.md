# 内容

他チームへ実装を依頼するときは、実現したい振る舞い、実行条件、満たすべき制約、必要な品質保証を明確にする。具体的な実装方式まで指定する必要があるかを考え、対象環境を管理する担当者が判断できる情報を渡す。

実装方式の選択は担当者へ委ねつつ、その方式で要件を満たせるかは確認する。責務の委譲によって要件を曖昧にせず、相手の専門領域まで依頼側が設計しない。

```text
## 実装方式ではなく実現したい要件を伝える

他チームへ実装を依頼する際、
具体的な実装方式まで指定する必要があるかを考える。

依頼する側が明確にすべきなのは、

- 実現したい振る舞い
- 実行条件
- 満たすべき制約
- 必要な品質保証

である。

具体的な実装方式は、
対象環境を管理する担当者へ委ねる。

ただし、実装方式が要件を満たせるかは確認する。

責務を委譲することと、
要件を曖昧にすることは異なる。

相手の専門領域まで設計するのではなく、
適切な判断に必要な情報を渡す。
```
