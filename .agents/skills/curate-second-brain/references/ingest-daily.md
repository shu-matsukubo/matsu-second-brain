# daily整理

## 制約

- 1回の実行で主対象にするdailyを1ファイルに限定する。
- 対象が見つからない場合は変更せず終了する。
- 共有仕様は `SKILL.md` のreferenceの選び方に従い、実際に必要になったものだけを読む。

## 手順

1. 最も古い未処理dailyを1ファイル選ぶ。
2. 入力に含まれる独立した主題と主張を確認し、既存knowledgeとsignalsに同じ意味がないか検索する。
3. `AGENTS.md` の大枠に従い、各部分をknowledge（fact・principle・idea）、signal、保存不要のいずれかへ振り分ける。knowledge候補の分類・配置・メタデータを判断するときは情報モデルを読む。signal候補が生じたときだけsignalsの共有仕様を読む。
4. knowledgeにする部分は、同じ主題のファイルがあれば1ファイル1主題を壊さない範囲で更新し、なければ現在のtypeとtopicへ小さなファイルを作成する。
5. ideaに必要なfactがなく、一次情報から確認でき、そのideaの理解に有用な場合だけ、必要最小限のfactを付随して作成する。既存factで足りる場合や検証できない場合は作らない。
6. knowledgeを作成または変更した場合は、その時点でIndexとリンクの共有仕様を読み、関連リンクとtopic Indexを更新する。signalを保存する場合は、signalsの共有仕様に従って月次ファイルへ短い箇条書きとして追加する。
7. 入力の意味をknowledgeまたはsignalsへ反映したか、保存不要と根拠をもって判断できた場合だけ、dailyを `status: processed` にする。

対象dailyに複数の独立した主題が含まれる場合、処理完了に直接必要な複数の小さなknowledgeを作ってよい。別のdailyや無関係な改善へ作業を広げない。

未検証の事実主張をfactにもsignalにも安全に振り分けられず、意味を失わず処理できない場合は、dailyのstatusを変更せず理由を報告する。
