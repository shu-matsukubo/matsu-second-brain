# daily整理

## 制約

- 1回の実行で主対象にするdailyを1ファイルに限定する。
- 対象dailyを処理する前に、[情報モデル](../../../references/information-model.md)、[Indexとリンク](../../../references/indexes-and-links.md)、[signals](../../../references/signals.md)を読む。
- 対象が見つからない場合は変更せず終了する。

## 手順

1. 最も古い未処理dailyを1ファイル選ぶ。
2. 入力に含まれる独立した主題と主張を確認し、既存knowledgeとsignalsに同じ意味がないか検索する。
3. 各部分を次のいずれかへ振り分ける。
   - fact: 信頼できる一次情報、実際の設定、再現可能な観測で確認する。
   - principle: 明示された判断基準か、すでに複数の根拠がある場合だけknowledgeにする。
   - idea: 未確定であることを保ち、理解に必要な既存factを探す。
   - signal: 単体では弱いが、再観測すると意味を持つ短い観測として保存する。
   - 保存不要: 長期価値も反復時の意味もない一時情報は別領域へ複製しない。
4. 同じ主題のknowledgeがあれば、1ファイル1主題を壊さない範囲で更新する。なければ現在のtypeとtopicへ小さなファイルを作成する。
5. ideaに必要なfactがなく、一次情報から確認でき、そのideaの理解に有用な場合だけ、必要最小限のfactを付随して作成する。既存factで足りる場合や検証できない場合は作らない。
6. 作成または変更したknowledgeの関連リンクとtopic Indexを更新する。signalを保存する場合は月次ファイルへ短い箇条書きとして追加する。
7. 入力の意味をknowledgeまたはsignalsへ反映したか、保存不要と根拠をもって判断できた場合だけ、dailyを `status: processed` にする。

対象dailyに複数の独立した主題が含まれる場合、処理完了に直接必要な複数の小さなknowledgeを作ってよい。別のdailyや無関係な改善へ作業を広げない。

未検証の事実主張をfactにもsignalにも安全に振り分けられず、意味を失わず処理できない場合は、dailyのstatusを変更せず理由を報告する。
