# signalsの記録と反映

dailyからsignalを保存するとき、または日次レポートの昇格候補を日次メンテナンスで反映するときに読む。signalの意味とknowledgeとの境界は `AGENTS.md` を基準にする。

## dailyから記録する

- `signals/YYYY/MM.md` の該当するテーマ見出しへ、1つの観測を1つの短い箇条書きで記録する。
- dailyの作成日など実際の観測日を付け、その年月のファイルへ保存する。
- daily本文や長い説明を複製せず、同じdailyから同じ意味のsignalを重複追加しない。
- `signals` ディレクトリまたは月次ファイルは、最初の実データを保存するときだけ作成する。

```markdown
## AIツール

- 2026-08-23: 管理対象が増えること自体をコストと感じた
```

## 日次レビューの昇格候補を反映する

1. 最新の日次レポートが示す根拠signalと既存knowledgeを再確認する。
2. 現在も根拠が十分で、既存knowledgeと重複しないことを確認する。日次レポートの観測だけを根拠に確定しない。
3. `AGENTS.md` に従い、適切なtypeとtopicの小さなknowledgeを作成または更新する。
4. `SKILL.md` のreference選択に従ってIndexとリンクの更新手順を読み、関連リンクとIndexを更新する。
5. 意味がknowledgeへ十分反映されたsignalの箇条書きだけを削除する。独立した未反映の意味が残るsignalは残す。
6. 空になったテーマ見出しや月次ファイルは残さない。

反映済みsignalを整理することで、同じ観測が毎日のレビューで同じ昇格候補にならないようにする。元の入力履歴はdailyに残るため、追加の履歴管理は作らない。
