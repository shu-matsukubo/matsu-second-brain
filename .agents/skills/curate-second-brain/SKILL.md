# 第二の脳を整理する

## 原則

- 1回の実行では、主対象を1ファイルに限定する。
- 変更を小さく保ち、レビューしやすい状態を維持する。
- ユーザーが処理方法を指定した場合は、その指定を優先する。
- 対象がない場合や有益な変更が見つからない場合は、変更せず終了する。
- 推測でナレッジを作成または更新しない。

## 処理を選択する

1. デイリーメモの処理を明示された場合は、ナレッジ化を選択する。
2. メンテナンスを明示された場合は、メンテナンスを選択する。
3. 処理方法が指定されていない場合は、[未処理メモの判定](references/find-unprocessed-daily.md)に従って `status: new` のメモを探す。
4. 未処理メモが見つかった場合は、ナレッジ化を選択する。
5. 未処理メモが見つからない場合は、メンテナンスを選択する。
6. 1回の実行で両方を行わない。

## デイリーメモをナレッジ化する

1. [デイリーメモ整理](references/ingest-daily.md)を読み、処理手順と完了条件に従う。
2. ナレッジへの反映方法は[ナレッジへの昇華](references/promote-to-knowledge.md)に従う。
3. 配置先を判断するときは[カテゴリ整理](references/categorize-knowledge.md)に従う。
4. 関連ノートを見直すときは[ナレッジ間のリンク](references/link-knowledge.md)に従う。

## 既存ナレッジをメンテナンスする

1. [ナレッジメンテナンス](references/maintain-knowledge.md)を読み、対象の選定方法と完了条件に従う。
2. 候補を比較するときは[メンテナンス優先順位](references/prioritize-maintenance.md)に従う。
3. 関連ノートを見直すときは[ナレッジ間のリンク](references/link-knowledge.md)に従う。

## 終了する

- 変更内容と対象が1件に収まっていることを確認する。相互リンクや処理済みステータスなど、主対象に直接付随する変更は許容する。
- 作業中に得た事実や気付きは、必要な場合だけ `AGENTS.md` のフィードバック方針に従って記録する。
- この処理で変更したファイルだけをまとめてコミットし、既存の無関係な変更を含めない。
- 実施内容、対象、変更しなかった理由がある場合はその理由を簡潔に報告する。
