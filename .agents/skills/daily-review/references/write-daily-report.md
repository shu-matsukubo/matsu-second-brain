# 日次レポート形式

## 保存先

- `reports/daily/YYYY`

## ファイル名

- `MM-dd.md`

## 書き込みルール

- 1日1ファイルを基本とする。
- 同日のレポートが存在する場合は現在の状態を再評価し、内容が変わる場合だけ更新する。
- 事実と観測を記載し、改善を強制しない。
- 必要に応じて改善候補へ優先度を付ける。
- 根拠を確認できない項目は断定しない。
- 件数だけでなく、再確認できるファイルパスや代表例を示す。
- 前回候補は現在の状態を確認し、解消済みか未解消かを区別する。
- 未処理dailyがある場合、改善候補より先にdailyが処理されることを明記する。
- レポートは観測時点の記録として残し、後の日次メンテナンスで候補が解消しても過去日のレポートを書き換えない。
- `reports/weekly` の既存ファイルは移行前の歴史的記録として保持し、移動または日次形式への書き換えを行わない。

## フォーマット

```markdown
# MM-dd 日次レポート

## サマリー

...

## 現在の設計との整合性

...

## knowledge品質

...

## Indexとリンク

...

## 活動状況

...

## signalsと昇格候補

- 対象:
  - 根拠:
  - 想定する反映先:
  - 既存knowledgeとの関係:

## 改善候補

### 高

- 対象:
  - 観測:
  - 根拠:
  - 完了状態:

### 中

- ...

### 低

- ...

## その他気付き

...

## 収束判定

- 特筆事項なし。
```

昇格候補がなければ `- なし。` とする。改善候補の各優先度に対象がなければ同様に `- なし。` とする。改善候補、昇格候補、設計差、その他の特筆事項がすべてない場合だけ、収束判定を `- 特筆事項なし。` とする。何か残る場合は、収束していない理由を短く記載する。
